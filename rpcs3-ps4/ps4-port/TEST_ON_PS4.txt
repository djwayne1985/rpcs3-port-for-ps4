========================================================================================
INSTALLATION (your settings and caches are preserved)
========================================================================================
1. Close the emulator using the PS > Close application button.
2. Copy the .pkg file to /data/pkg and install from GoldHEN
   (Debug Settings > Package Installer). It only updates the emulator;
   does not affect the PS4 system.
3. Do not delete /data/rpcs3/cache: the game cache is reused.

========================================================================================
GAMES AND FIRMWARE
========================================================================================
- Folders in /data/rpcs3/games/NOME (PS3_GAME/USRDIR/EBOOT.BIN), ISO in
  /data/rpcs3/games or USB:/PS3ISO, PKG from PS3 to /data/rpcs3/pkgs.
  Also read are /data/rpcs3/PS3ISO, pkg, packages, iso and gamez
  (uppercase or lowercase doesn’t matter).
- Folder disc game: games/Nome/PS3_GAME/... AND games/Nome/PS3_DISC.SFB
  (without PS3_DISC.SFB the game will not open). PSN game in folder: the folder
  with the name of the TITLE_ID (games/NPUB30554/PARAM.SFO + USRDIR/EBOOT.BIN).
  Each game in its subfolder: never direct content in games/.
- Licenses: <CONTENT_ID>.rap (16 bytes) in /data/rpcs3/raps or USB:/raps,
  then "Import .rap licenses".
- PKG: leave twice the size of the PKG free on the PS4. Update that requests a
  version you don't have: "Do you want to install it anyway?" (X Yes installs,
  Circle Does not cancel; to undo, delete dev_hdd0/game/<TITLE_ID> at
  FTP). PKG still copying: X warns "still copying" and does not install.
- FTP (0.37): after the emulator opens once, the games, pkgs,
  raps, import, patches, custom_configs, data, data/redump, data/disc-lock
  and exdata from /data/rpcs3 accept files (startup.log "folders: 10
  ready for FTP").
- FTP (0.39): open RPCS3 once BEFORE sending files. Folders
  created by FileZilla (or an entire dev_hdd0 copied by FTP) are
  blocked for the emulator; with the FTP of the GoldHEN ON, the RPCS3
  fixes this by itself when opening (NEWS FROM 0.39, item 7).
- ISO (0.39): a ISO never asks for the disc on the reader; ISO encrypted
  opens without manual .dkey (key is fetched by itself); ISO incomplete
  appears as "ISO incomplete: X GB missing" (NEWS FROM 0.39, items
  2 to 4); ISO without the PS3 disk header (made from a folder by
  a common ISO) program opens (item 6).
- PS3 firmware extracted from /data/rpcs3/dev_flash.
- Emulator package does NOT include games, firmware or licenses: use
  just copies of your own games.

========================================================================================
PS3 FIRMWARE (like PC RPCS3 "Install Firmware")
========================================================================================
- Games require official PS3 firmware, which is not included in the package.
  On PC, download PS3UPDAT.PUP from the official PlayStation website (support page
  PS3 system update). It's the PS3 update, not the PS4 update:
  a PS4UPDATE.PUP is refused.
- Copy to a pendrive (exFAT or FAT32) in PS3/UPDATE/PS3UPDAT.PUP (a
  same folder that the PS3 uses) or in the root of the pendrive. By FTP too
  worth /data/rpcs3/import/PS3UPDAT.PUP. The search order is: pendrive
  PS3/UPDATE, pendrive root, /data/rpcs3, /data/rpcs3/import.
- XMB > Settings > "Install PS3 Firmware" > X. The file is
  checked as on PC (header, size and signature of each part;
  takes a few seconds). 0.38: The system window "Do you want to install the
  firmware 4.92?" shows the file, its version and the installed version:
  installs, Circle (No) cancels.
- Installation shows the "Installing..." window with the bar ("Package i of
  n", "Do not turn off the system."); while it is open XMB waits
  and no game opens. Circle (or X) in the window asks "Do you want to cancel
  firmware installation?": X (Yes) cancels, Circle (No) continues.
  Once the folder change begins, you can no longer cancel it (it takes a while).
  instant).
- You need around 550 MB free on the PS4 HD. First the package
  installation (update_files.tar, ~190 MB) is copied from the PUP to
  /data/rpcs3/dev_flash.installing and checked ("copying the
  PS3UPDAT.PUP to /data"); After that the pendrive is no longer read.
  New firmware is mounted in the same folder, each file is written in
  fact on the disk (fsync) and only then change the /data/rpcs3/dev_flash.
- The previous firmware is stored in /data/rpcs3/dev_flash.old until
  NEXT application opening. The new firmware is checked there
  (version.txt equal to the installed one and the main files present):
  OK, XMB says "Firmware X checked" and dev_flash.old is deleted;
  wrong, the previous one comes back on its own and XMB warns you. If there is no space,
  cancel, the application closes or there is a power outage in between, there is a
  firmware only (the previous one or the new one) and the message says which one ("the
  4.90", "runs out of firmware"). The state is in dev_flash.state.
- The pendrive is only readable. The emulator never changes the system update
  on PS4: PS3UPDAT.PUP is only read and turns files into /data/rpcs3.
- "System Information" shows the installed version. Without firmware, the
  XMB prompts when opening and points to this item.
- startup.log: lines "firmware: ..." (file found, check,
  installed version and time).

Test
1. No firmware: XMB opens with "PS3 firmware not installed".
2. Pendrive with PS3/UPDATE/PS3UPDAT.PUP: Settings > Install
   PS3 firmware > X. The question appears with the version (e.g.: 4.92).
3. X: the "Installing..." window with the bar; XMB waves continue
   cheering behind her.
4. At the end: the "Installation is complete." with "Firmware 4.92
   installed... the previous one is stored until the next opening" (X
   OK); System Information shows "Firmware 4.92"; the
   XMB icons and font are reloaded; /data/rpcs3/dev_flash.old
   exists (FTP).
5. Wrong file (PS4UPDATE.PUP renamed, incomplete download): a
   message says the reason and the installed firmware does not change.
6. Remove the pendrive during "Verifying" or "copying PS3UPDAT.PUP":
   the message says about a disconnected pendrive (not a file
   corrupted), starts with "Firmware not installed, remains <previous>"
   upon installation and the previous firmware continues.
7. Circle during "Installing...": Cancel question appears.
   Circle (No): Installation continues. X (Yes): "Installing the
   firmware canceled: <previous> remains".
8. Close and open the application after step 4: XMB says "Firmware
   4.92 checked in this opening" and then the dev_flash.old disappears
   (startup.log: "passed the check at start"). Open again: none
   warning.
9. Install again and close the application (PS button > Close application)
   in the middle of "Installing firmware". Open again: XMB tells you which
   firmware remained (the previous one, or the new one "checked"); information
   system shows the same; dev_flash.installing some (FTP). Don't test
   unplugging the PS4: this risks the PS4 system itself (the
   installer was made to handle it, no need to test it on the console).

========================================================================================
CONTROLS
========================================================================================
- XMB: Left/Direita = category; Up/Baixo = item; X = open/iniciar;
  Circle = return; Triangle = update list (and import .rap);
  Square = configure the game; R1 = game patches; L1 = clear the
  game cache.
- 0.40: in the "Game" column, the Triangle opens the Options (folders, item 17);
  the first, "Update Game Library", does what Triangle
  did (updates the list, imports .rap, reads the reader): Triangle and
  then X. In the other columns the Triangle continues to update.
- Return from the game to XMB: press L1 + R1 + Triangle together and hold
  1 s (or L1 + R1 + Options for 2 seconds).
- Exit: PS button > Close application (the game pauses by itself first), or the
  item "Exit RPCS3 PORT FOR PS4" on XMB.

Up to 4 players
- Each extra controller requires a user logged in to the PS4: press the
  PS button on the new controller and choose a user or "Guest".
- Player 1 = blue, 2 = red, 3 = green, 4 = pink (color of light).
- The XMB "Users" column shows who is in each vacancy.
- Any control navigates to XMB.

     startup.log "cellAudio: PS4 audio policy: HR waits on, reserve 64
     ms, wait up to 64 ms while reserve > 16 ms, idle after 100 ms,
     continuity auto". Settings saved at 34 ms change to 64 once
     ("profile: 'Desired Audio Buffer Duration' saved by automatic
     profile <=37 ('34') -> 39 ('64')").
   - Volume and audio adjustments from the PS button menu (in-game)
     are valid immediately ("Updating cell_audio_thread configuration").
   - "Renderer" in this audio menu: the PS4 only has one sound output, so
     "Null" does not mute the game (the output is recreated and the sound continues).
     To mute the sound, use volume.
   - Mixer error lines in RPCS3.log (_sys_lwmutex_lock ESRCH
     "Invalid ID", sys_mutex_lock EDEADLK, sys_mutex_unlock EPERM on
     audio threads) are normal: the PS3 does the same.
   - The 10s AudioOut line won " reserve_waits=N late_max_ms=X
     late<5/5-10/10-20/20-40/>40=... idle_ports=N rate=0.xx
     avg_time=0.xx".
9. Crashes and crashes (all games)
   - Shader interpreter crashes after a few minutes
     ("Verification failed... VKProgramPipeline.cpp") has been fixed
     (interpreter-sync-link.flag is the emergency exit).
   - GTA IV and similar freezing: the emulated GPU reads and writes the
     sync tags without going through memory protection
     (rsx-label-direct.flag returns to the old way); the order of ZCULL
     on a page fault (zcull-av-upstream.flag) and a network
     security for a page fault that repeats endlessly
     (no-av-livelock-net.flag).
   - After a video thread crash, the game stops and XMB shows the
     error window. Until 0.38 a game thread could get stuck
     waiting for the video thread, which had already died, and the PS4 closed
     the application in 10 s (PS4 home screen, without the warning in XMB).
     startup.log "PS4 RSX: a CPU fault at 0x... waited for the RSX
     thread, which ended in a fatal error; not served, left to the
     access-violation net so the stop can finish" (on OpenGL, "PS4
     OpenGL:..."). With no-av-livelock-net.flag there is no more waiting
     end and the PS4 closes the application as in 0.38.
   - Fake warning "the game appears frozen": on first boot Fallout New
     Vegas copies about 2.6 GB to the HD (about 7 minutes) with the slider
     its progress (a system message window, which RPCS3
     draw). With this window on the screen the game does not send frames, and at 0.38
     recorded STALL dumps and showed "RPCS3: the game appears to be stuck ha N
     s. ..." with the game running. Now a message window from
     system on the screen counts as activity (while the video thread
     is alive), and a lot of reading and writing files through the game too.
     startup.log, once per boot: "STALL: no guest flip for 25 s while
     a native message dialog is on screen; RSX loop N ms ago: counted as
     activity, no STALL dump and no 'game looks frozen' toast
     (stall-strict.flag restores the 0.38 rule)" (or "while the game
reads or writes files (N calls in 5 s)"). A real crash
     (no window and no files) continues with the dump and the warning.
     stall-strict.flag returns to the 0.38 rule.
   - Threads: threads that have ended are released (the PS4 refused new ones
     and the game would mute or return to the menu); a rejected creation is
     retried once (thread-no-retry.flag); camera, microphone and
     other service threads only start when the game uses
     (keep-service-threads.flag); stopping the game doesn't need a thread
     new. startup.log "PS4 threads: ...".
   - Starting order of PPU threads (Plants vs. Zombies): one thread
     new one with lower or equal priority no longer makes whoever created it wait,
     like on PS3 (ppu-start-wait.flag goes back to waiting for RPCS3). startup.log
     "PPU threads: sys_ppu_thread_start returns at once ...".
   - Game frozen due to invalid memory access ("The PS3" screen
     application has likely crashed"): return to XMB with "The game
     emulated crashed (invalid memory access in '<thread>'): returned to
     menu"; another game opens without reopening RPCS3 (frozen-stays.flag leaves
     frozen as in 0.38).
   - GPU that stops responding for 10 s: the game closes and returns to XMB
     ("GPU: confirmed hang (...): stopping to the XMB (no-hang-stop.flag
     keeps waiting)"); in the next 3 openings this game uses "Async
     Recompiler" without the shader interpreter ("RPCS3 warning: tuning
     automatic for <ID> after previous failure: shaders without interpreter
     (GPU crashed)"). no-hang-stop.flag waits forever, like in
     0.38.
   - Optional: dead-fifo-stop.flag does a "Dead FIFO" (the game video
     stopped) return to XMB instead of "Error in emulator".
   - After an error, the window shows the first line of the reason. If the
     game opened alone by boot-next closes again with the same error,
     XMB says "<game> closed again with the same error: reopen RPCS3
     does not resolve" and does not ask to reopen again.
   - A savestate that could not be read in the previous session is warned
     ("Previous session: a savestate of <ID> could not be read...").
10. Performance
   - Video driver shader cache (Mesa) turned on by default in
     /data/rpcs3/cache/mesa (up to 512 MB): the second opening of a game
     compiles far fewer shaders (Vulkan and OpenGL). startup.log "Mesa shader
     cache: /data/rpcs3/cache/mesa/ (512 MiB, ...)". mesa-cache-off.flag
     turns off; the old mesa-cache.flag is no longer accurate.
   - Shader interpreter links go in front of the shaders
     queue game (interp-no-lane.flag); shader compilation only
     Wait your turn with tight memory (level 2 or more).
   - Emulated GPU rings grow on their own when a game needs it
     (startup.log "ring ... grew 8 -> 16 MiB"; the next boot of the game will already
     starts bigger); rings-no-grow.flag turns off.
   - Video memory: empty blocks return to the system when the window
     press (vma-keep-empty.flag).
   - More accurate short game waits (HR timer from 30 µs;
     precise-sleep-spin.flag returns to 40 µs); the governor of memory
     uses new rules (governor-v038.flag returns to 0.38).
   - "Cold mode" on first opening: compiling the game ("Compiling
     PPU Modules" and "Building SPU Cache") uses up to 2 threads instead of 1,
     without the extra threads
     (in 0.38, with Cold Mode turned on, the first boot of Fallout New
Vegas took about 90 minutes, with 88 minutes of PPU in one thread). During
     the game builds continue one at a time (so areas
     new ones are a little slower in Cool Mode). startup.log "cool
     mode: compile stage (PPU modules, SPU cache) runs on at most 2
     compile threads, in optional workers; compiles during play stay
     serialized". cool-mode-serial-boot.flag returns to the 0.38 way (a
     compilation at a time also on opening).
11. OpenGL (Game Settings > GPU > Renderer: OpenGL)

     strict crashes the emulated GPU in Zink); zcull-strict-gl.flag returns to
     strict. Settings saved by 0.37/0.38 in OpenGL are transferred to the
     relaxed once.

   - OpenGL's "RSX gameplay" line shows "GL program compiles N (ms)"

1. Close by PS button after playing (CE-34878-0): a small thread
   ("GNM keepalive") prompts the PS4 GPU (sceGnmSubmitDone) 0.5 s later
   that the emulator stops sending work to it, again every 1 s
   stopped and every 250 ms while the system asks to suspend. Without
   this warning the PS4 was unable to suspend the application and closed it
   (KLog from 0.35 shows "Can't suspend ... submitDone() is not called"
   with the GPU stopped, "busy:0"). no-gnm-keepalive.flag turns off.
2. God of War: Ascension: while the emulated GPU waits for a semaphore that
   SPU will write, pending occlusion (ZCULL) results are
   sent to the GPU and checked without crashing; if after 50 ms still
   are pending, they are forcibly read. It was the 0.35 circle: SPU
   it only started when this result arrived, and it was only recorded
   after waiting. rsx-no-report-drain.flag turns off (only for
   compare: GoW crashes again).
3. Video memory (Wolverine's closing at ~23 min): the ring of
   vertices no longer jumps from 64 to 128 MB: old frames are
   released before and, if there is still space left, it grows from 16 to 16 MB
   (up to 128 MB) or wait for the GPU ("ring ... grew" or "recovered by hard
   sync" in startup.log); heavy VRAM cleaning that doesn't free anything
   remains 10 s without rotating instead of rotating every frame; descriptor pools
   of GPU programs stopped for more than 20 s are returned.
   ring-reclaim-off.flag and no-pool-release.flag turn each part off.
4. Second game without closing the application (e.g. inFamous, XMB, Mortal
   Kombat): the Vulkan loader used the first instance, already
   destroyed, and the game closed with SIGABRT. Now use the live instance.
5. Network: the P2P socket no longer blocks, the game accept no longer crashes and a
   test at the beginning ("network ABI: SO_NBIO...") finds out if the PS4 lets
   non-blocking sockets. If left, RPCN can connect via
   first time.

   - an abort() now says in the "reason:" line of fatal.txt who called it
     (address in rpcs3_ps4.elf), the assert message before it and the
     /data/tempest-vkloader.log's "FATAL" line when he was the charger
     from Vulkan;
   - STALL shows the status of each SPURS ("STALL SPURS 0x...: wklFlag=
     ... receiver=... readyCount[..]=... signal1=...");
   - "GPU: a command buffer submitted N ms ago has not finished" warns
     a crashed GPU;
   - the first copies back from the GPU are in the log ("DMA: readback
     #N ...") and a copy with impossible parameters is refused ("DMA:
     rejected readbacks N").

   turns on if the start test passes ("HR reuse ... -> reuse OK"); without the

HOW TO READ NEW LOG LINES (0.34)
========================================================================================
- RPCS3.log, every 10 s with sound playing:
    AudioOut: blocks=1875 underruns=U concealed=C callback_lock_misses=0;
    cellAudio: periods=P game_late=.. host_late=H (max .. us)
    in_progress_waits=.. silent=.. untouched_waits=W wait_ms=T drops=D
    ring_min_ms=R
  blocks=1875 = the PS4 output played everything it should in 10 s.
  underruns = blocks (of 5.33 ms) that arrived empty or half full:
  the bigger, the more perky (0.33: 382 to 818 in the opening video of the
  Wolverine, 5 to 46 after him). concealed = of these, how many
  turned to fade instead of silence. periods = blocks that game audio
  produced (1875 = on time; 1500 = 20% late). host_late = times
  the emulator itself woke up late (if greater than 0, test
  audio-high-priority.flag). untouched_waits / wait_ms = waits for
  game. drops = blocks thrown away with the buffer full. After the
  Continuous audio kicks in ("game-paced audio" line in
  startup.log; 0.39: "automatic continuity engaged") appears "
  stretch=on ratio=0.85" (0.39: never below 0.70); with
  audio-fine-poll.flag, " assist=on poll_ms=N" (assist=off in windows
  where the game is not delayed).
- startup.log, every 10 s: "RSX gameplay: F FPS ..." (game FPS), with
  "pipelines: skipped draws=..." (drawings missed by shader
  compiling), "present src rt=.. tex=.. cpu=.. switches=..; tag
  misses=.." (where the image shown came from).
- startup.log "VDEC perf (...)": codec, decode avg/max, busy, pace=,
  GetPicture conversions=N to argb conv=sse avg=X ms.
- RPCS3.log every 60 s: "ATRAC3plus: N AUs/s, decode avg X us max Y us,
  D decoders" (only in games with ATRAC3plus audio).
- startup.log, up to 8 per game: "cellAudio: port N started: C channels,
  B blocks, attr 0x..., notify queues Q" (each game sound output).
- startup.log: the line that samples each optional file from part 2:
    audio-poll-2ms.flag "cellAudio: block poll 2 ms"
    audio-no-conceal.flag "AudioOut: underrun concealment off"
    audio-auto-stretch.flag "cellAudio: automatic time stretching
                              armed" (and, when turned on, "game-paced audio");
                              0.39: ignored ("audio-auto-stretch.flag
                              ignored: automatic continuity is the
                              default")
    audio-fine-poll.flag "cellAudio: fine block poll armed"
    audio-high-priority.flag "cellAudio: audio threads at priority"
    vdec-sws-convert.flag "VDEC: vdec-sws-convert.flag: GetPicture RGB
                              conversion through swscale"
    vdec-release-slot.flag "VDEC: GetPicture releases the PPU run slot"
    vdec-slice-threads.flag "VDEC: mpeg2video slice threading requested"
                              (or "H.264 slice threading requested")
    present-hold-ms.txt "RSX: frames that lost draws ... held up to"
                              (wrong value: "present-hold-ms.txt ignored")
    vk-fast-pipelines.flag "RSX: pipelines compiled while 4 or more are
                              pending are linked without driver
                              optimizations"
    vk-compile-3.flag " Vulkan shaders with 3 threads" on line
                              "PS4 Policy for..." (or
"vk-compile-3.flag no effect (reason)")
    zcull-strict-on-read.flag "ZCULL: CPU reads reports at ...; strict
                              report sync from now on" (only when the game
                              reads results by CPU)
    ppu-priority.flag "PPU: host priority raised above SPU threads"

TEMPERATURE AND COOL MODE
========================================================================================
- PS4 won't let apps read the temperature sensor: on all
  tested consoles (Slim and Pro) the reading returns with error 0x80020002
  (ENOENT). This is why the emulator CANNOT warn or pause the game
  by temperature. What the startup.log shows:
    "thermal: no reading (ENOENT), try 1 of 3; ..." (try 3 times:
    at the beginning, after 60 s and 300 s);
    "thermal: sensor unavailable (ENOENT); the emulator cannot pause on
    heat, the PS4 firmware protects the console" (after the 3rd);
    in the "health:" line of each minute, "temperature unavailable
    (ENOENT)" until the 3rd attempt; after it (0.36) the line does not speak
    over temperature ("n/a" only before the first reading; "off
    (no-thermal.flag)" with this file).
- The one who protects the console is the PS4 itself (fan, console warning
  too hot, shutdown).
- Ventilation: 10 to 15 cm free around the air vents, no rack
  closed, cloth or rug; Clean dust from air inlets and outlets.
- "Cool mode (less heat)" (RPCS3 Settings): less CPU spent
  waiting idly, less heat and noise; some games lose a little
  FPS, more in new areas (during the game the builds run one of
  each time). 0.39: the first opening "Compiling PPU Modules" uses
  up to 2 threads (in 0.38, just one; cool-mode-serial-boot.flag returns to
  this). Worth it
  from the next game. Create /apaga file
  /data/rpcs3/cool-mode.flag.
- The emulator never changes the fan, clock, power or
  PS4 system.

6 to 45 minutes (large games, up to about an hour). A
only once; the next time it opens much faster. Let it finish: no
close the application during this step. In 0.40 the first boot of each
game builds the SPU cache again ("Building SPU Cache", a few minutes,

opening compiles one thing at a time, like in 0.38 (with the

========================================================================================
GAMES ON EXTERNAL HD OR PENDRIVE (like on PS3)
========================================================================================
Prepare the disc (on PC)
- Format in exFAT (recommended: accepts ISO larger than 4 GB). FAT32
  it also works, but only with files up to 4 GB; ISO divided into
  parts (.iso.0, .iso.1...) is not read.
- PS4's "extended storage" will NOT work: it is encrypted
  via the console and the emulator cannot read it. Use a HD or pendrive
  common formatted on PC (NTFS is not read by PS4).
- Create folders at the root of the disk (the same names as multiMAN/webMAN;
  uppercase or lowercase doesn't matter):
    PS3ISO .iso files (can use subfolder: PS3ISO/RPG/jogo.iso)
    GAMES one folder per game, with PS3_GAME/USRDIR/EBOOT.BIN inside
    PKG .pkg packages from PS3 (X installs on PS4)
  Also read: ISO and PKG loose at the root, GAMEZ, PACKAGES and
  PS3/GAMES. Inside
  each, at most two subfolders deep are searched
  (e.g. PS3ISO/RPG/Japo/jogo.iso), so that a large disk can be read
  fast; the rest of the disk is not searched. PKG from PS4 on the same disc
  (those from GoldHEN) do not appear in the emulator list.

Use
- Plug the disc into any USB port on the PS4 (fat, slim or pro).
- In the Game column, each game says where it comes from: "PS4" (/data/rpcs3) or
  "USB 1", "USB 2"... The Network column shows, below "Storage of
  games", each disc and how many games it has.
- Connect or disconnect with the XMB open: within 2 seconds the list
  updates itself ("USB 1 connected: N game(s)" or "USB 1
  disconnected"). Games from a disconnected disc disappear from the list and
  return when it is turned on again. Triangle reads all disks
  again (use after copying games over the network to disk; since
  0.40, in the Game column: Triangle > "Update game library").
- Disc connected without games: a line appears saying what is missing
  ("no PS3ISO, GAMES or PKG folders", "no games in the folders" or
  "disk could not be read"; in this case, Triangle tries again,
  as above).
- Disc only with PKG from PS4 (PKG folder from GoldHEN): the line says "only PKG
  from PS4"; they do not enter the count or the game list.
- The first read of a disc with many games may take a few
  seconds; XMB continues to respond. Then the list comes from the cache.
- The game opens directly from the disk, which is read only: nothing is written to it.
  Cache, saves, settings, licenses and updates are on the PS4, in
  /data/rpcs3. An installed update also applies to the ISO of USB.
- PSN game in folder (without PS3_GAME) does not open from USB, because it
  would write its data to disk: copy the folder to /data/rpcs3/games
  or install PKG. ISO and folder disc games open normally.
- Do not remove the disc with the game open. If you remove it, the game may stop with
  error; when you return, XMB warns "USB 1 has been disconnected".

Test
1. exFAT flash drive with PS3ISO/jogo.iso: connect with XMB open. In until
   2 s appears "USB 1 connected" and the game with "USB 1 ·" in the subtitle.
2. Open the game, play, come back (L1 + R1 + Options). Nothing new in
   flash drive; the cache is in /data/rpcs3/cache.
3. Remove the pendrive with the XMB open: the game disappears in up to 2 seconds.
4. Empty pendrive: the line "USB 1: without folders..." appears.
5. startup.log: lines "library: USB 1 (/mnt/usb0)", "USB hot-plug:"
   and "XMB loader (...): ... usb polls N avg ... ms".

- In the game list, hover over the game and press L1, then X to

========================================================================================
IF THERE IS A PROBLEM
========================================================================================
- The message appears on the screen and again at the next start.
- Records of the last 8 sessions are in /data/rpcs3/log/history/0..7
  (startup.log, RPCS3.log, mesa.log, fatal.txt).
- ALWAYS send all three together: startup.log, RPCS3.log and mesa.log from
  same session, copied after closing RPCS3 (see CONSOLE TESTING
  DA 0.40). Just RPCS3.log is not enough: startup.log tells you what the
  emulator did on PS4 (memory, threads, folders, disk, language, and the
  line "features:" with what was linked). Also send the
  /data/rpcs3/adapt/<TITLE_ID>.txt of the game, if it exists.
- A failed game opens next time in safe mode (NEWS FROM
  0.40, item 4): the warning says the level and the reason. Leave it like that and play;
  If it only works in secure mode, send the logs of both sessions
  (the one that failed and the one in safe mode).
- Do not choose the PPU or SPU interpreter in the settings of a
  game: on PS4 it is 10 to 50 times slower than LLVM (the game is
  with 1 or 2 FPS). 0.39 notifies you when a game opens with it.
- Also send /data/orbis-abort.log and /data/tempest-vkloader.log (FTP,
  directly in the /data folder): they tell you who called an abort() and which function
  of Vulkan was missing.
- If the screen stops, wait 1 minute before closing with the PS button.
- "The emulator needs to restart after the previous error": close by button
  PS > Close the application and open it again.
- "Emulator memory exhausted (2 GB): game closed" (startup.log
  "fatal: thread failed with the heap at its cap"): just close and open the
  application returns this memory. Send the logs for that game.
